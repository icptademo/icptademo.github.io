Azure 的账单看不懂，常常是因为把订阅、资源组和标签当成了同一个东西。再加上「我已经关机了」和「门户里显示已释放计算」不是一回事，月底的数字会对不上。下面只讲结构和几个会反复出现的坑，不写单价。价格以你订阅所在区域的定价页为准。

## 订阅、资源组、标签各管一件事

订阅是计费和访问控制的边界。资源组是订阅里面的逻辑容器，用来把同一套生命周期的资源放在一起，方便一起部署和一起删除。给资源组指定的区域，只决定这份资源组元数据存在哪里。组里的虚拟机、磁盘可以在别的区域。官方说明见[在门户中管理资源组](https://learn.microsoft.com/azure/azure-resource-manager/management/manage-resource-groups-portal)。

标签是键值对，成本分析可以按它筛选。写在资源组上的标签，不会自动出现在组里已有的资源上。要继承，得用 Azure Policy，或者在每个产生费用的资源上单独打。成本分析读的是资源自己的标签。

在 [Azure 门户](https://portal.azure.com) 里可以这样分：

1. 搜索「订阅」，确认你正在看的订阅 ID 和发票上的一致。
2. 进入该订阅 → 资源组。生产和试验不要放在同一个组里，否则一键删除会把两边一起带走。
3. 给生产资源打 `env=prod` 这类标签。名称先定一张小表，不要每个人随手写 `Prod`、`prod`、`production`。

管理组在订阅之上，用来挂策略，不代替订阅付钱。谁能看成本，还取决于订阅或账单范围上的 Cost Management 角色。范围说明见[了解 Cost Management 范围](https://learn.microsoft.com/azure/cost-management-billing/costs/understand-work-scopes)。

付款方式随协议变化：在线开通的即用即付通常绑卡，通过微软代表签署的协议常常走电汇。这五家的差别见[付款与账单对比]({% post_url 2026-10-30-five-clouds-billing %})。

## 预算到了也不会停机

成本管理和计费 → 成本管理 → 预算 → 添加。也可以先打开订阅，再在左侧选预算，这样范围不会选错。官方教程写明：超过阈值会发通知，资源不受影响，消耗也不会停。数据通常在 8 到 24 小时内出现，预算大约每 24 小时评估一次，评估之后邮件一般在一小时内发出。所以今天下午的消费，不要指望五分钟后告警。见[创建和管理预算](https://learn.microsoft.com/azure/cost-management-billing/costs/tutorial-acm-create-budgets)。

创建时注意两个容易误解的选项：

- 重置周期选每月、每季或每年。文档说明季度预算会把金额均分到三个月，年度预算会均分到十二个月。你以为的「这一季一共多少」，评估时是按月往下拆的。
- 到期日在未来时，预算到周期结束会按同一金额自动重置。到期之后预算会被删除。金额每个月不一样，就要分成多条预算，而不是建一条然后指望它自己变。

邮件收件人写成值班邮箱。只发给订阅创建者，而那个人已经离职，告警就断了。人员变动时改收件人，放进[交接清单]({% post_url 2026-11-03-account-handover-checklist %})。

命令行可以列出已有预算，但这组命令仍标记为预览，创建以门户为准：

```bash
az consumption budget list
```

## 关机之后还在计费

虚拟机的电源状态直接决定计算费用。文档中的对应关系是：从客户机操作系统里关机，状态常常是 Stopped（已分配），计算继续计费；在门户或用 API 执行停止并释放，状态变为 Stopped (deallocated)，计算不计费。磁盘和网络资源在已释放之后仍可能计费。见[虚拟机状态与计费](https://learn.microsoft.com/azure/virtual-machines/states-billing)。

先看真实状态，再决定要不要释放：

```bash
az vm list -d --query "[].{name:name, rg:resourceGroup, power:powerState}" -o table
az vm deallocate --resource-group RG --name VM
```

释放之后如果这台机器不再使用，还要处理留下来的部分：

- 数据盘经常不会随虚拟机一起删除。系统盘是否一起删除，取决于创建虚拟机时的选项。
- 仍挂在网卡上的公网 IP 可能继续产生费用。删虚拟机时看删除确认框里列出的资源，删完再打开资源组扫一遍磁盘和 IP。
- 预留实例的费用跟这台虚拟机开不开机无关，预留到期前都会记在账单上。

另一个方向是删得太猛。资源组上如果有 `CanNotDelete` 锁，整组会删不掉。备份保管库里还有恢复点时，也会挡住删除。先看锁和备份，再删组。

## 成本分析怎么对上资源

成本管理 → 成本分析。筛选订阅，再按资源组、服务或标签分组。新订阅第一天图表可能是空的，等数据延迟过去再下结论，不要据此判断「还没花钱」。

对得上的习惯是：一个环境一个资源组，标签从创建时就打上，试验资源单独订阅或至少单独资源组。预算按这个范围各建一条，而不是全订阅只有一个很大的数字，谁超了都看不出来。

## 当天核对

- 门户里的订阅 ID 和发票、付款邮件上的一致。
- 生产资源组里没有试验用的虚拟机。
- 至少一条月度预算，邮件发到有人看的地址，并且你知道它不会停机。
- 抽一台「关掉」的虚拟机，电源状态是 Stopped (deallocated)，资源组里没有被遗忘的磁盘。

订阅、发票抬头和付款方式最好在第一笔生产消费之前分开。需要按企业主体协助开通 Azure 的，看[大牛云的开户说明](https://www.daniucloud.com/open)。
