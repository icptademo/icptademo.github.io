选国际云时，Logo 和「全球地域数量」帮不上忙。先回答六个问题，再打开购买页：用户在哪些国家、能接受的延迟是多少；账单会不会被公网出流量主导；要的是通用 CPU、GPU，还是现成的媒体和加速产品；数据必须留在哪个司法辖区；团队已经会哪一套 API；这个地域今天能不能买到你要的规格。最后一个要用购买页或地域接口核对，不要用新闻稿。腾讯云国际的查法见[如何查询各地域可售产品]({% post_url 2026-11-02-tencent-cloud-regions %})，其他云同样先看本账号的购买页。

一家主云、一个主地域，先把权限、账单告警和备份做完。多云只在玩家必须分区、目标 GPU 没货，或合同要求数据分开放时再加。为了架构图上有五个 Logo 而拆系统，监控和账单会先垮。

## 游戏：按玩家集群分区，把带宽单独算

游戏服的延迟预算是几十毫秒量级的体验问题，不是把全球玩家接到一个「中心区域」就能解决的。按玩家所在的网络分区：东南亚、日韩、欧洲、美国东岸和西岸通常不是同一组服务器。状态同步、匹配和数据库跟游戏服放在同一地域的私网里。跨地域用各云的全球加速或云联网类产品，不要让帧同步走公网绕一圈。

开服当天的在线人数不可靠。已经测过延迟的地域，再用包年或预留锁定单价；没测过的地域先按量或弹性组，避免把错误区域锁进长期合约。安全组默认拒绝，管理端口不要对 `0.0.0.0/0` 开放。

DDoS 是上线清单的一部分。五家都有基础防护和可以加钱的增强防护，清洗阈值、回源价格和是否按攻击流量计费差很多，以当前产品页为准。被打的那一天再去开通，往往来不及，也更贵。

算账单时把三项拆开：实例、出方向流量、防护。流量用「从机房所在地域，到玩家所在地区」的单价，不用厂商首页上的起步价。玩家主要在某个国家时，选该国或邻近地域，往往比选「机器最便宜的地域」更省，因为跨洋流量和丢包会同时出现。

中国大陆玩家和海外玩家不要放进同一套假设。国际站地域不能代替中国站对大陆业务的合规要求。需要同时服务两边时，当成两个发布区域来设计，而不是在国际站上找一个「顺便能覆盖大陆」的机房。

阿里云国际和腾讯云国际在亚太地域、中文控制台和游戏团队已经熟悉的产品名上，常常是先做验证的那一家。玩家分布更散、团队已经在用 AWS 的网络和账号体系时，常见的是 AWS 上的分区服加上 Global Accelerator 这一类入口。这是部署习惯，不是性能排名。真正的取舍仍是：目标地域有没有你要的机型、到玩家的实测延迟、以及流量单价。

## 音视频：先分开互动和分发

语聊、连麦、互动直播看的是最后一公里和区域覆盖，常常直接用各云或第三方的实时音视频产品，而不是买一台很大的 CPU 自己做转发。选的时候问三件事：目标国家有没有接入点、弱网下的策略能不能配、计费按分钟还是按带宽。没有接入点的「全球一张网」，延迟数字只在厂商自己的测试城市里成立。

点播和单向直播是另一条链路：转码、对象存储、CDN。转码可以在源站地域批量做，播放必须靠离用户近的 CDN。热视频、冷视频和日志使用不同的存储层级和生命周期，避免全部堆在标准存储里。

国际站 CDN 的节点和中国站用于加速大陆的节点不是同一张网。用户主要在海外，就在海外买 CDN，并看目标国家的节点而不是全球节点总数。用户主要在大陆，大陆加速是否允许、要不要备案，按那个站点当时的规则单独确认。不要用海外 CDN 去绕开大陆的合规要求。

成本不要折成「一台 GPU 服务器每月多少钱」。转码按分钟或按路、存储按 GB 月、CDN 按 GB 出流量，三个数分开估，再加回源流量。回源打到另一个洲，是点播账单里最常见的隐藏项。源站、存储和主要观众放在同一地域，回源才便宜。

## AI 训练：跟着库存和数据走，不跟着公司注册地走

训练任务看三件事：加速卡在目标地域有没有配额和库存、多机之间有没有高速互联、数据集在不在同一地域。推理才更在意离用户的延迟。公司注册在新加坡，不表示训练就该放在新加坡。

新账号的 GPU 配额经常是 0。付款成功也不等于能开高阶加速卡。在真正需要的日期之前提交配额申请，并准备一个有库存的备选地域。AWS、Google Cloud、Azure、阿里云国际和腾讯云国际都提供 GPU 实例，具体型号和可选地域每周都可能变，以购买页为准，不要引用几个月前的评测文章当库存。

Google Cloud 除此之外提供 TPU。它不是 NVIDIA GPU 的别名，框架、镜像和地域库存都要单独查。团队的代码如果绑死了某一种 CUDA 版本，先确认目标实例的驱动和镜像，再比较单价。

多机训练不是把任意两台 GPU 虚拟机放进同一个 VPC。需要实例支持的高速网络（各家名称不同，例如 AWS 文档中的 EFA 这一类能力；其他云有自己的 RDMA 或 RoCE 机型）。单机微调用不到这些，不要为了参数表好看去买多机规格。

可中断的预处理和部分训练可以用抢占式或 Spot 实例，单价通常低一截，机器也会被收回。检查点必须先写到同一地域的对象存储，收回之后能从对象存储恢复，而不是从本地磁盘恢复。

数据集放在训练同一地域。把几十 TB 数据从另一个洲拉过去，出流量费用可以超过两家 GPU 的差价。数据因合规不能出境时，训练地域跟着数据走，卡型不够就改训练方案或换有该地域库存的云，而不是先把数据复制出境再看合同。

## 做决定的顺序

1. 写下一个主用户国家和一个主数据所在地。两个答案不同时，游戏和音视频优先迁就用户，训练优先迁就数据。
2. 在两到三个候选地域打开购买页，确认 CPU 或 GPU 规格真实可售，并记录出方向流量单价。
3. 用按量资源做一次延迟或吞吐试验。试验账号上先打开账单告警，阈值设得低一些。
4. 选定一家主云之后，再处理根账号或主账号、子账号和付款方式。技术选型定不了付款，但付款失败会在试验做到一半时停掉资源。五家的账单结构见[付款与充值对比]({% post_url 2026-10-30-five-clouds-billing %})。
5. 只有在主云的目标地域买不到卡、或玩家区域和数据驻留无法用同一家云覆盖时，再引入第二家。第二家也要有自己的账号保护和账单告警，不要共用个人密钥。

场景定下来之后，还要确认主体、地域和付款方式能一起落地。开户和方案可以对照[大牛云的业务场景说明](https://www.daniucloud.com/solutions)，回到各云官网核对地域与配额之后再下单。
